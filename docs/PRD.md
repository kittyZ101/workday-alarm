# 上班脑 · PRD（Product Requirements Document）

> 产品一句话：**你只配一次排班，以后系统自己知道每天要不要响闹钟。**
> 适用对象：有「大小周 / 单休 / 双休 + 法定调休补班」需求的中国上班族。

---

## 1. 背景与问题

中国的上班节奏里，有全球少见的两种日子：

- **法定调休**：法定节假日前后用周末补班，形成「连休几天 + 后面周六/周日上班」。
- **公司排班**：大小周、单休、双休，以及公司自定义的加班/放假日。

这些规则叠加后，「明天到底上不上班、闹钟响不响」变成一件每周都要人肉判断的事。现有工具的问题：

| 问题 | 现状 |
| --- | --- |
| 通用日历只认识「周末」 | 不知道补班、调休、大小周 |
| 系统闹钟只能固定重复 | 「每周六 7:00」无法表达「大小周里只有小周周六响」 |
| 第三方 App 不能直接改 iOS 系统闹钟 | 必须借助系统能力绕路 |
| 每个同事各算各的 | 排班口径不一致，分享后难以同步 |

目标：把「排班规则」和「闹钟动作」彻底解耦，做成**傻瓜式一键安装**。

---

## 2. 目标与非目标

**目标**
- 用户配置一次排班，得到一份准确的中国工作日历。
- 日历可一键订阅，同事打开即同一份排班，且更新自动同步。
- iPhone 用户配好后，闹钟按「今天是否上班」自动开/关，**包含周日补班、法定放假、大小周周六**。
- 安装流程尽量傻瓜式：最少人工步骤、图文/深链引导、失败可自检。

**非目标（MVP 不做）**
- 轮班 / 夜班 / 倒班 / 三班倒等复杂排班。
- 多个不同起床时间的闹钟。
- 直接修改 iOS 系统闹钟时间（系统不允许第三方写闹钟）。
- 账号系统、团队后台、审批流（后续版本再考虑）。

---

## 3. 用户与核心场景

- **A：大小周员工**：最痛。周六上班是否响，每周都变。
- **B：双休员工**：主要痛点是调休补班（周日补班也容易漏）。
- **C：单休员工**：周日休、周六上班，需要法定放假时周六也不响。
- **D：分享者（行政/组长）**：做好排班发链接，同事一键收。

核心场景：睡前或周一早上确认「这周哪天响」，以及早上系统自动判断「今天响不响」。

---

## 4. 名词定义

| 名词 | 含义 |
| --- | --- |
| 工作日 | 需要上班、闹钟应响的日子 |
| 休息日 | 不上班、闹钟不应响 |
| 法定假日 | 官方放假（可能落在工作日） |
| 补班日 | 官方调休后需上班的周末，可能是周六或**周日** |
| 小周 / 大周 | 大小周排班：小周周六上班，大周周六双休 |
| 上班日日历 | 只含「上班日」事件的专用日历，作为闹钟判断的事实源 |

---

## 5. 核心设计原则

1. **日历是唯一事实源**：所有复杂规则（大小周、调休、补班、手动纠正）最终都收敛成「每个日期是上班还是休息」，写入日历。
2. **闹钟只做二值判断**：闹钟逻辑不包含任何日期规则，只回答「今天日历里有没有上班事件」→ 有就开，没有就关。
3. **规则与动作解耦**：国家调休变了，只更新日历；闹钟和快捷指令永远不用改。
4. **无状态、可分享**：排班规则可编码进链接/订阅地址，不依赖账号即可传播。
5. **先求准确，再求傻瓜**：正确性优先于自动化，任何不确定都给用户可见结果。

---

## 6. 日历与闹钟的兼容机制（核心）

### 6.1 为什么能兼容补班

把「今天是否上班」做成一张决策表，日历和闹钟天然对齐：

| 今天 | 「上班日」日历 | 快捷指令动作 | 闹钟「上班日」 |
| --- | --- | --- | --- |
| 周一至周五上班 | 有事件 | 开 | 响 |
| 双休周六 / 周日 | 无事件 | 关 | 不响 |
| 大小周·小周周六 | 有事件 | 开 | 响 |
| 大小周·大周周六 | 无事件 | 关 | 不响 |
| 法定放假（含工作日） | 无事件 | 关 | 不响 |
| 调休补班（含**周日**） | 有事件 | 开 | 响 |

关键点：**补班不管落在周六还是周日，都只是日历里的一条「上班」事件**，所以同一套闹钟逻辑自动覆盖，不再需要为「周六补班」「周日补班」分别处理。

### 6.2 判定优先级

排班引擎按以下顺序决定某天状态（高→低）：

1. 用户手动纠正（`overrides`：强制上班 / 强制休息）
2. 调休补班日（`makeupWorkdays`）
3. 法定假日（`holidays`）
4. 基础排班规则（双休 / 单休 / 大小周 + 基准周）

前两项覆盖中国式调休，后两项覆盖公司节奏，手动纠正兜底。

### 6.3 iOS 闹钟实现路径

iOS 不允许第三方直接开/关系统闹钟，因此采用系统能力组合：

- **日历订阅**：`webcal://…/ics?d=配置&alarm=1`，生成名为「上班脑闹钟」的订阅日历，只含上班日。
- **快捷指令「大小周闹钟」**：
  - 读取「上班脑闹钟」日历中**今天**的事件；
  - 事件数 > 0 → 打开闹钟「上班日」；
  - 否则 → 关闭闹钟「上班日」。
- **自动化**：每天早上固定时间（默认 06:30，必须早于闹钟）运行该快捷指令，关闭「运行前询问」。
- **闹钟**：用户只需建**一条**闹钟「上班日」，每天重复，时间固定（如 07:00）。

这样把「大小周 + 调休 + 周日补班」全部交给日历，快捷指令只做一次性的、不变的开关动作。

## 7. 功能需求

### 7.1 排班配置（P0）
- 支持三种模式：双休 / 单休 / 大小周。
- 大小周可设置「基准周一」和「该基准周是否小周」。
- 官方节假日多年份结构，内置 2026 基线，2027/2028 待公布占位；支持在线更新。
- 手动纠正：任意日期强制「上班 / 休息 / 恢复自动」，且与官方数据互斥冲突时给明确提示。
- 提供本月 / 本周视图与统计（上班天数、休息天数、补班天数）。

### 7.2 日历生成与订阅（P0）
- 生成两种 ICS：
  - 「上班脑工作日历」：全量，含上班 / 休息 / 放假 / 补班标签，供人看。
  - 「上班脑闹钟」：只含上班日，供闹钟自动化消费。
- 支持 `webcal://` 一键订阅（iOS），Google 日历订阅（安卓/桌面）。
- 无状态订阅：排班配置编码进 URL，服务端即时生成，无需存储用户数据。
- 订阅覆盖「当前年 + 未来两年」，避免跨年失效。

### 7.3 闹钟自动化（P0，iOS）
- 快捷指令按日历名「上班脑闹钟」匹配，不硬编码 UUID。
- 快捷指令动作：读今天事件 → 计数 → 条件开关闹钟「上班日」。
- 引导文案明确：闹钟标签必须叫「上班日」；自动化时间必须早于闹钟；「运行前询问」必须关闭。

### 7.4 安装向导（P0）
- 按 UA 分流：iPhone / 安卓 / 电脑，显示对应步骤。
- iPhone 四步：订阅日历 → 下载快捷指令 → 建「上班日」闹钟 → 建自动化。
- 每步提供一键深链 / 复制按钮 / 图文说明。
- 提供「自检」能力：提醒用户检查日历是否订阅成功、快捷指令是否导入、闹钟名是否匹配。

### 7.5 分享（P1）
- 分享链接（无后端也能用，排班编码进 URL）。
- 订阅链接（后端部署时可用，作者更新自动同步）。
- 各改各的排班：打开分享后编辑只影响本机，不与分享源冲突。

## 8. 安装流程（便捷安装设计）

### 8.1 iPhone（目标 ≤ 4 步）
1. 点「一键添加闹钟日历」→ 系统弹「订阅」→ 确认。
2. 点「一键导入快捷指令」→ 下载 `.shortcut` → 文件 App 打开 → 添加。
3. 在时钟 App 建一条闹钟「上班日」，每天重复。
4. 在快捷指令 App 建一条自动化：每天 06:30 → 运行「大小周闹钟」→ 关闭「运行前询问」。

> 前两步是一键，后两步是系统限制下的固定动作；引导页用图文/短视频把门槛降到最低。

### 8.2 安卓（MVP）
- 订阅 Google 日历查看排班；手动开关闹钟。
- 进阶：用 Tasker / MacroDroid 读日历并控制闹钟，提供教程。
- 长期：做安卓原生 App，用 AlarmManager 自动开/关闹钟，成为真正的安卓傻瓜式。

### 8.3 桌面
- 订阅日历到系统日历 / Outlook / Google 日历，主要用于查看。

## 9. 可靠性 / 边界情况

| 边界 | 处理 |
| --- | --- |
| 周日补班（如 09-20） | 通过「每天自动化 + 上班日闹钟」覆盖，已修复 |
| 自动化时间晚于闹钟 | 引导校验并提示：自动化时间必须早于闹钟（建议早 30 分钟） |
| 跨天判断 | 自动化在早上运行，判断「今天」；不处理凌晨跨日闹钟 |
| 调休数据更新 | 更新官方基线并发布，订阅日历自动刷新；最长次日生效 |
| 时区 | 统一 `Asia/Shanghai`，ICS 写 `X-WR-TIMEZONE` |
| 闹钟名不匹配 | 引导强调标签必须为「上班日」，并提供自检 |
| 快捷指令首次权限 | 引导说明需允许快捷指令访问日历/闹钟 |
| 自动化「运行前询问」未关 | 引导明确必须关闭，否则不会自动执行 |
| 数据口径冲突 | 手动纠正优先级最高，冲突时 UI 明确提示 |

## 10. 技术架构（现状与目标）

- **前端**：Vue 3 + Vite + PWA（可添加到主屏幕）。
- **后端**：Express（自托管）+ Vercel Serverless（`/ics` 无状态生成）。
- **数据**：官方调休基线内置在前端（`src/core/holidays.js`），用户配置存 `localStorage`；订阅走 URL 编码，无服务器存储。
- **核心模块**：
  - `schedule.js`：排班判定引擎（`statusOf` / `infoOf`）。
  - `ics.js`：ICS 生成。
  - `shareCode.js`：配置编码/解码。
  - `AlarmGuide.vue`：安装向导。
  - `大小周闹钟.shortcut`：快捷指令文件。

## 11. 里程碑

- **M0（已完成）**：日历 + 排班 + 分享 + 无状态订阅 + 初版快捷指令。
- **M1（已完成）**：闹钟方案升级为「每天自动化 + 上班日闹钟」，修复周日补班漏响；重写安装向导；加入自检。
- **M2（已完成）**：官方节假日多年份结构 + 在线更新通道（`/holidays.json`）；2027、2028 已占位，待官方公布后填入。
- **M3**：安装体验打磨（图文/短视频、故障自检、安装完成率埋点）。
- **M4**：安卓原生 App（自动闹钟）。
- **M5**：账号 / 云同步 / 团队分享 / 双端上架。

---

## 12. 成功指标

- **安装完成率**：从打开引导到「闹钟能响」的转化率。
- **漏响 / 误响率**：用户反馈中，调休/补班日闹钟错误的次数。
- **手工操作减少**：用户每周手动开/关闹钟次数。
- **分享传播**：分享链接被打开次数、订阅人数。

## 13. 待确认问题

- 是否需要支持多个闹钟 / 不同起床时间（周末晚起 vs 工作日早起）？
- 大小周用户是否需要「周六上班」和「工作日」不同时间？
- 节假日数据源是否只依赖内置基线，还是需要接入可更新的官方数据源？
- 安卓 MVP 是否接受「先订阅日历 + 手动开关」，还是要求直接做自动闹钟？
- 是否需要团队协作（行政统一排班、成员只读同步）？

- 月历 / 本周 / 统计。
- 全量工作日历 ICS 下载、无状态订阅（`/ics?d=...`）。
- 分享链接、各改各的排班、编辑口令。
- 快捷指令「大小周闹钟」（每天自动化 + 上班日闹钟）与 iPhone 四步引导 + 装完自检。

- 安卓自动闹钟（M4）。
- 账号 / 云同步 / 团队分享（M5）。
